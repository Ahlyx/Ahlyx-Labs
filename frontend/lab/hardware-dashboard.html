Hardware Dashboard

A small public window into aggregate CPU, memory, disk, and network telemetry from the Ahlyx Labs backend host.

A window into the host behind the site

Hardware Dashboard is intentionally small: it shows aggregate telemetry from the Ahlyx Labs backend host. Opening it answers a limited but useful question—what are this server's CPU, memory, disk, and network readings right now? It is not a diagnostic agent installed in the browser, and it does not inspect a visitor's computer.

That distinction is the point. The dashboard is a public operational view of one host, not a remote-support tool or a generalized machine inventory. The hosted implementation is Go-backed and separate from the older Python Hardware Dashboard repository.

Published aggregates, not host inventory

Ahlyx Labs backend host → Go hardware handlers → hosted dashboard → aggregate metrics

The browser requests the metrics exposed by the hosted service. The service reports generic operating-system information, CPU usage and core counts, memory and swap totals, aggregate disk capacity and I/O, and aggregate network counters. The frontend refreshes those panels; it does not ask the browser for local hardware details.

The public response is intentionally narrower than a complete host inspection. It avoids hostnames, IP addresses, interface inventories, mount points, filesystem detail, and OS-version information. That keeps the dashboard useful as a quick status window without turning it into a map of the backend's infrastructure.

Using the public view

There is no local install or agent to configure for the current utility—open the hosted dashboard. A panel failing to load is a service condition, not a signal about the visitor's device.

The historical Python project is included in the references because it is related by name and subject, not because it powers this page. It was a separate local CLI and dashboard project; the live Ahlyx Labs utility is the Go-backed backend telemetry view described here.

Deliberately limited telemetry

These are aggregate readings for one backend host. They are not promises about availability, performance, security posture, or the health of every dependency behind the site. Values can change between refreshes and may be unavailable when the service cannot collect or publish a metric.

More detail is intentionally excluded. The dashboard does not expose sensitive host identity, interface, IP, mount, filesystem, or patch information, and it never reads a visitor's local CPU, RAM, storage, or network traffic.
