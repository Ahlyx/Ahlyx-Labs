Baptisia

An experimental domain-specific language for ICS/OT control programs that compiles .ba source to C and includes a simulation stack.

Status: Experimental / R&D

Last reviewed: 2026-09-17

View source on GitHub →Browse projects →

Overview

Baptisia explores compiler-enforced structure for industrial-control programs. It is intended for learning, experimentation, and reviewing how a DSL can arrange validation, safety checks, control logic, and outputs. A concrete use is compiling a pump-control example with a latched failsafe and then observing it through the included simulation.

What currently works

The reviewed source describes a Go lexer, parser, semantic analysis, C code generator, HAL, and physics simulation. It compiles .ba files to C and has simulation mode for linking generated control logic to the HAL and physics engine.

Roadmap

This is experimental R&D. The project does not claim industrial deployment, physical safety guarantees, or certification.

How it works

.ba source → lexer → parser → AST → semantic analysis → C output
                                              ↓
                                    HAL and simulation stack

The language encodes structural patterns such as input validation and safety checks before control logic. Those compiler constraints are not a substitute for an engineering safety case, field validation, or certified controls.

Getting started

Building the reviewed project requires Go 1.21+ and GCC. Clone the source and run go build ./.... The README documents go run main.go motor.ba for a standard compile and go run main.go -sim "test files/OR_logic.ba" for simulation-oriented output.

Security, privacy, and limitations

The generated structural order cannot establish that a deployed physical process is safe. Sensor assumptions, actuators, hardware, integration, commissioning, and operational controls remain outside this compiler. Treat flags and simulation results as development evidence, not industrial certification.
