PCAP Agent

A local Go program that summarizes selected packet metadata in memory and streams it to a browser dashboard, with an optional confirmed metadata relay.

Status: Local tool + hosted dashboard

Last reviewed: 2026-09-17

Open tool →View source on GitHub →Browse projects →

Overview

PCAP Agent gives an operator a local capture-and-dashboard workflow for traffic metadata. It is for investigation and visibility, such as checking local flow, DNS, statistics, and conservative observations while using an explicitly selected interface. It is not an IDS, firewall, or proof that observed traffic is malicious.

What currently works

The source documents TCP, UDP, and ICMP capture through libpcap/Npcap; flow and DNS metadata; protocol statistics; top talkers; and conservative retransmission, reset, periodic-connection, and scan observations. The hosted dashboard is maintained separately from the local agent.

How it works

selected interface → local Go agent → in-memory metadata → loopback WebSocket → browser dashboard

Default local mode listens on loopback and the hosted dashboard connects to ws://localhost:7777/ws. Relay mode asks for explicit confirmation before metadata is sent through the service. Raw packet payloads are not sent in WebSocket messages or relayed.

Getting started

Install the local capture dependency and permissions for the platform: Npcap and an elevated terminal on Windows, libpcap headers and appropriate capture permissions on Linux, or macOS libpcap with suitable privilege. Build with Go 1.22+, CGO, a C compiler, and the capture headers, then run pcap-agent start. See the source README for platform commands and release archives.

Security, privacy, and limitations

Capture privileges and drivers are required; encrypted protocol content is not decrypted. The default filter excludes non-TCP/UDP/ICMP traffic. Observations are heuristics: periodic connections, resets, retransmissions, MAC properties, or port-scan signals are not proof of compromise. DNS visibility is query/answer metadata only; the project does not claim DNS-tunneling detection, and enrichment is not wired into the capture pipeline.
