PCAP Agent

A local network-observability tool that turns selected packet metadata into a browser dashboard without relaying raw payloads.

Status: Local tool + hosted dashboard

Last reviewed: 2026-09-18

Open tool →View source on GitHub →Browse projects →

Local visibility, not a remote packet feed

PCAP Agent is for looking at traffic on a network interface you have chosen and are allowed to capture from. It uses libpcap or Npcap to observe TCP, UDP, and ICMP traffic, keeps selected metadata in memory, and makes that information available to a browser dashboard. It is a practical way to inspect flows, DNS activity, protocol statistics, top talkers, and a few deliberately conservative observations without pretending to be an IDS.

The local agent and the hosted dashboard are separate pieces. In normal local mode, the dashboard running in a browser connects back to an agent on the same computer over a loopback WebSocket. The website does not reach into a visitor's network on its own, and the agent does not bundle the production dashboard.

Capture locally, share metadata deliberately

selected interface → local Go agent → in-memory metadata → loopback WebSocket → browser dashboard

The capture filter is installed before packets enter the analysis path. PCAP Agent tracks flow and TCP-session metadata, DNS questions and available answers, aggregate counters, protocol distribution, and MAC/vendor context. It can point out periodic connection attempts, retransmissions, resets, and possible scan patterns, but those are observations for investigation—not proof that a host is compromised.

By default the agent listens on 127.0.0.1 and the Ahlyx Labs dashboard uses ws://localhost:7777/ws. Raw packet payloads are neither placed in WebSocket messages nor sent to the relay. Optional relay mode requires confirmation before flow metadata is sent to the service and gives the operator a session-specific dashboard URL.

What it takes to run

Live capture has platform realities. Windows needs Npcap and an elevated terminal; Linux needs libpcap headers plus an appropriate capture permission; macOS uses libpcap with suitable privilege. Building from source also needs Go, CGO, a C compiler, and capture headers. Prebuilt releases avoid the build toolchain but not the capture driver and permission boundary.

The normal workflow is to start the local agent, let it select an interface or choose one explicitly, and then open the dashboard. A virtual adapter, VPN, VM, or container host is a good reason to inspect the available interfaces rather than relying on automatic selection.

pcap-agent list-interfaces
pcap-agent start --interface <interface>

What the observations mean

Encrypted protocol contents are not decrypted. The default filter intentionally excludes traffic outside TCP, UDP, and ICMP. DNS support is query and answer visibility only; PCAP Agent does not claim DNS-tunneling detection, and threat-intelligence enrichment is not wired into the capture pipeline.

Network behavior is noisy. A retransmission can be normal loss, a reset can be routine teardown, a locally administered MAC can be a privacy feature, and a burst of connections can come from ordinary software. Possible scan and periodic-connection alerts are intentionally conservative clues that need packet context, endpoint ownership, and operator judgment before they become a security conclusion.
