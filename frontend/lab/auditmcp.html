AuditMCP

A local-first proxy that sits between an MCP client and server, records tool calls in a local SQLite audit log, and redacts likely secrets before storage.

Status: Local tool

Last reviewed: 2026-09-17

View source on GitHub →Browse projects →

Overview

AuditMCP addresses the gap between an MCP client's tool use and a reviewable local record. It is for people who want to inspect their own tool-call history while using a compatible MCP server. A typical use is wrapping an MCP server command in a client configuration, then using query, verify, or export after a session.

What currently works

The maintained source documents stdio and loopback HTTP proxy modes, a hash-chained SQLite log, likely-secret redaction before persistence, and query, verification, and JSONL export commands. It forwards MCP traffic and records tool-call activity; it is not a vulnerability scanner or authorization gateway.

Roadmap and scope

The proposed policy-gateway phase is cancelled. The stated scope is a local, single-user audit proxy; maintenance focuses on compatibility, fixes, and dependencies.

How it works

An MCP client sends traffic to AuditMCP, which forwards it to the selected server while placing matching tool-call records on a dedicated local write path. Before an entry is stored, likely secrets are redacted; the resulting entries are chained for later verification.

MCP client → AuditMCP proxy → MCP server
                 │
                 └→ local SQLite audit log → query / verify / export

The log is tamper-evident rather than tamper-proof. Its documented fail-open runtime design means a tool call proceeds if logging fails after startup, rather than making the proxy a blocking dependency.

Getting started

Use a release archive for the local platform or build from source with stable Rust. For a stdio server, the basic shape is:

auditmcp run -- npx -y @some/mcp-server
auditmcp query
auditmcp verify

Configuration is optional for the default per-user state location. The maintained README lists Rust as the build prerequisite and Python 3 only for its fake-server tests and examples.

Security, privacy, and limitations

AuditMCP is local-first: its documented default has no telemetry, accounts, cloud dependency, or network calls of its own. Pattern-based redaction cannot guarantee that every secret is found. A hash chain provides evidence of changes within the recorded chain, not an absolute guarantee against every form of deletion or tampering.

Interactive OAuth is not supported by the transparent proxy because client/server identity checks prevent that setup. HTTP listeners are loopback-only; the project does not provide authorization for arbitrary network exposure.
