Security Enrichment

A maintained Go service that gathers context for IP addresses, domains, URLs, and file hashes from configured third-party sources.

Status: Live service

Last reviewed: 2026-09-17

Use tool →View source on GitHub →Browse projects →

Overview

Security Enrichment helps an analyst collect source-specific context without treating one lookup as a final verdict. It is useful when reviewing a public IP, domain, hash, or public URL and comparing returned source outcomes. Missing source data is not evidence that an indicator is safe.

What currently works

The maintained service validates each input type, makes configured source requests, returns normalized responses with source metadata, and supports a browser tool. Available sources vary by input, configuration, quotas, and failures. URLScan active submission is optional and separately gated.

Roadmap

The maintained source is the Go implementation in Ahlyx Labs. The prior public enrichment repository is historical and does not define this API.

How it works

indicator → validation → configured source requests → normalized response + source outcomes

Some upstream failures can still produce a partial response. Responses are cached server-side according to source outcomes: one hour when all sources succeed, 15 minutes when only some succeed, and not cached when all fail. URL responses tell clients and intermediaries Cache-Control: no-store; that does not disable the server-side cache.

Getting started

Use the hosted enrichment tool for interactive lookups. API consumers should only send benign public indicators and should not submit passwords, tokens, private reset or invitation URLs, or other sensitive values.

API

Base URL: https://api.ahlyxlabs.com. No visitor API-key authentication is implemented through the public edge. CDN controls may affect scripted access; origin verification is an operator/edge control, not a credential visitors should send.

Method and pathPurpose
GET /healthHealth response.
GET /api/v1/capabilitiesReports urlscan_active_submission.
GET /api/v1/ip/{address}IP context.
GET /api/v1/domain/{name}Domain context.
GET /api/v1/hash/{hash}Hash context.
POST /api/v1/urlURL context; JSON request body required.
GET /api/v1/urlDeprecated; returns 410 Gone.
curl 'https://api.ahlyxlabs.com/api/v1/ip/8.8.8.8'
curl 'https://api.ahlyxlabs.com/api/v1/url' -H 'Content-Type: application/json' --data '{"url":"https://example.com","submit_urlscan":false}'

URLScan submission happens only when deployment enablement and explicit submit_urlscan: true opt-in are both present. It can disclose a URL to a third party. The default example does not submit. There is no advertised Swagger or OpenAPI endpoint.

Configured per-client buckets replenish at 30/minute for IP/domain/hash and 10/minute for URL, with additional shared and CDN limits possible. Invalid input can return 400, throttling 429, an origin denial 403, and the retired GET route 410. Backend errors use {"error":"message"}; CDN errors can differ.

Sanitized response shape: {"query":"https://example.com","query_type":"url","timestamp":"...","sources":[...],"url":"https://example.com","safe_browsing":null,"urlscan":null,"virus_total":null,"is_malicious":false}. Null or absent source data should be interpreted as unavailable context, not a clean result.

Security, privacy, and limitations

External sources, quotas, configuration, and network conditions affect coverage. URL lookup uses POST specifically so indicator URLs are not placed in query strings. Upstream data and heuristic verdict fields need contextual analyst review, and no result is an SLA or a guarantee of safety.
